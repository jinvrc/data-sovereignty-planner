# Backup & Distribution Strategist

## Описание
Предлагает схему распределения ваших данных по 2–3 независимым хранилищам (облачным и локальным) так, чтобы ни один провайдер не был единственной точкой отказа. Учитывает бюджет, частоту обновления, скорость доступа, юридическую юрисдикцию и ваши привычки.

## Входные данные
- Инвентаризация из первого скилла (или аналогичный список)
- Бюджет (в месяц или разово)
- Предпочтения по скорости доступа и географии
- Ограничения по трафику и объёму

## Выходные данные
- Таблица распределения: какие данные куда переместить (например, «текущие проекты → Google Drive, архив → внешний SSD, резервная копия → Backblaze»)
- Расписание автоматического резервирования (инструменты и периодичность)
- Расчёт стоимости по месяцам
- Список бесплатных альтернатив с их условиями (ограничения по объёму, сроку)

## Рабочий процесс
1. На основе инвентаризации выделите группы данных по частоте доступа и критичности.
2. Подберите для каждой группы подходящее хранилище (облачное, локальное, гибридное).
3. Учтите бюджет и географическую доступность (если важна скорость в вашем регионе).
4. Предложите конкретные инструменты синхронизации (rclone, Resilio Sync, системные средства).
5. Опишите сценарий восстановления при отказе основного хранилища.

## Пример использования
> «Разработай стратегию, чтобы мои рабочие файлы и личный архив не зависели от Яндекса. Бюджет — до 500 руб/мес. Нужна комбинация: один основной облачный провайдер + один резервный + внешний диск. Учти быстрый доступ к последним проектам.»

## Принципы дизайна
- Не менее 2 независимых копий, географически разнесённых (если возможно).
- Расчёт стоимости с учётом трафика и будущего роста объёма.
- Упор на открытые и проверенные инструменты.
- Все рекомендации сопровождаются ссылками на документацию.
