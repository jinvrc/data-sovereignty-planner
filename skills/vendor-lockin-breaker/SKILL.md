# Vendor Lock‑in Breaker (План миграции)

## Описание
Пошаговый план выгрузки данных из проблемного сервиса в другие хранилища с минимальным перерывом в доступе. Оценивает объём, скорость канала, структуру папок, метаданные (общие ссылки, права доступа) и даёт чёткую последовательность действий.

## Входные данные
- Проблемный провайдер (название, объём, структура данных)
- Целевые провайдеры (из стратегии)
- Сроки, технические ограничения (скорость интернета, свободное место на локальном диске)
- Важно: сохранить ли общие ссылки и права доступа

## Выходные данные
- Календарный план с этапами (день 1: экспорт метаданных, день 2: загрузка на целевой, ...)
- Оценка времени (в часах) на каждый этап
- Рекомендации по конвертации форматов (если нужно)
- Чек-лист для проверки целостности после переноса (сравнить хеши, количество файлов)
- Инструкция по уведомлению контактов о смене ссылок (если есть общий доступ)

## Рабочий процесс
1. Составьте полный список файлов и папок (с метаданными).
2. Рассчитайте время выгрузки/загрузки на основе скорости соединения.
3. Определите порядок: сначала наименее критичные данные, потом критичные.
4. Выполните тестовый перенос небольшой папки.
5. После успешного теста — полная миграция с проверкой.
6. По окончании — удаление данных у старого провайдера (по желанию).

## Пример использования
> «Разработай план миграции моих 16 ГБ с Яндекса на Google Drive и внешний SSD. У меня скорость 50 Мбит/с, могу выделить 3 вечера. Сохрани все общие ссылки и структуру папок.»

## Принципы дизайна
- Поэтапность, возможность отката на каждом этапе.
- Все действия проверяемы (контрольные суммы).
- Учитываются временные зоны и доступность поддержки.
- Предусмотрен план Б, если что-то пойдёт не так.
